# Release workflow

A release requires a project-specific target, selected changes, version rule, verification commands, and publication authority. Establish each from the current repository and a human decision. Present the exact release candidate and checks before changing remote refs or publishing artifacts.

If any release input is not configured, stop at a read-only proposal. Do not infer a production branch, container command, CI server, or tag scheme from package metadata or prior projects.
